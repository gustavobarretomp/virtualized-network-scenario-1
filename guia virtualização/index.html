Instalar o VirtualBox

Ferramenta base — sem ela nada funciona
01
Baixar e instalar o VirtualBox
O VirtualBox é o hypervisor — ele cria e gerencia todas as suas VMs
▶
// POR QUÊ VIRTUALBOX?
O VirtualBox é gratuito, roda em Windows/Linux/Mac, e permite criar redes internas isoladas — exatamente o que você precisa para simular os segmentos de LAN e os links WAN entre roteadores. O professor também mencionou ele no quadro como opção principal.

1. Acesse virtualbox.org/wiki/Downloads e baixe a versão para o seu sistema operacional.

2. Também baixe o VirtualBox Extension Pack — ele habilita recursos extras como USB e clipboard compartilhado.

3. Execute o instalador e aceite todas as opções padrão. Quando perguntar sobre instalar drivers de rede, confirme — isso é necessário para as redes virtuais funcionarem.

4. Depois de instalar o VirtualBox, abra ele e vá em Ferramentas → Extensões → instalar o Extension Pack que você baixou.

// ATENÇÃO
Se você usa Windows 11 com Hyper-V ativado (para WSL2), pode haver conflito. Para verificar: abra o PowerShell como admin e rode bcdedit /set hypervisorlaunchtype off e reinicie. Só faça isso se o VirtualBox não iniciar as VMs.

Criar a VM base (template) — R1 como exemplo
Você vai criar uma VM, instalar o Ubuntu, e depois clonar ela para economizar tempo
▶
// ESTRATÉGIA: VM TEMPLATE + CLONES
Em vez de instalar o Ubuntu Server 10 vezes, você instala uma vez, configura o básico, e depois clona essa VM. É como tirar uma cópia de um documento. Isso economiza horas de trabalho.

No VirtualBox, clique em Novo e configure assim:

CONFIGURAÇÕES DA VM TEMPLATE

Tipo:          Linux
Versão:        Ubuntu (64-bit)
RAM:           512 MB  (suficiente para servidores de rede)
CPU:           1 núcleo
Disco:         10 GB   (VDI, alocação dinâmica)

Durante a instalação do Ubuntu Server:

→ Idioma: English (mais compatível com comandos de rede)

→ Usuário: admin, senha: admin123 (anote!)

→ Quando perguntar sobre pacotes extras, marque apenas OpenSSH server — isso te deixa acessar a VM via SSH do seu computador host.

→ NÃO instale interface gráfica — você quer o servidor mínimo.

Após instalar, atualize o sistema:

Configurar as redes internas no VirtualBox
Os "cabos virtuais" entre as VMs — o conceito mais importante do projeto
▶
// COMO FUNCIONA A REDE INTERNA DO VIRTUALBOX
No VirtualBox, quando você cria uma "Internal Network" com um nome (ex: lan1), qualquer VM conectada a essa mesma rede se comporta como se estivesse no mesmo switch físico. É como plugar vários computadores no mesmo cabo. Duas VMs com Internal Network "wan_r1r2" se comunicam diretamente entre si, isoladas do resto.

Você vai precisar das seguintes redes internas. O nome é o que liga as VMs entre si — tem que ser exatamente igual em cada VM conectada.

Clonar a VM template para criar todas as outras
Economiza horas — você instala o Ubuntu uma vez e copia para todos
▶
// POR QUÊ CLONAR?
Clonar cria uma cópia independente da VM. Ao contrário de um snapshot, o clone é completamente separado — você pode modificar um sem afetar o outro. Use clone completo (não vinculado) para garantir independência total.

Passos para clonar no VirtualBox:

1. Clique com botão direito na VM-Template → Clonar

2. Nome: R1 → tipo: Clone completo → Finalizar

3. Repita para criar: R2, R3, R4, R5, DNS1, DNS2, WEB1, EMAIL1, EMAIL2, PC-A, PC-B, PC-C, PC-D

4. Após clonar cada VM, configure os adaptadores de rede dela (conforme a tabela acima)

// IMPORTANTE — MUDAR O HOSTNAME
Após iniciar cada clone, mude o nome da máquina para saber qual VM é qual:
sudo hostnamectl set-hostname R1
Depois edite /etc/hosts e troque "ubuntu" por "R1" nas linhas relevantes.
3

Configurar os Roteadores (R1 — R5)

FRRouting com RIPv2 — o coração da rede
06
Instalar o FRRouting em cada roteador
FRRouting é o equivalente open-source do Cisco IOS — suporta RIPv2, OSPF, BGP
▶
// O QUE É O FRROUTING?
FRRouting (FRR) é um suite de roteamento gratuito para Linux. Ele foi criado como fork do Quagga (que era fork do GNU Zebra). O professor mencionou ele no quadro como ferramenta open source. Ele usa a mesma sintaxe de comandos do Cisco IOS — então show ip route, router rip, version 2 funcionam igualzinho ao Packet Tracer. A diferença é que é Linux real, não simulação.

Rode estes comandos em cada VM de roteador (R1 a R5):

INSTALAR FRROUTING — RODAR EM CADA ROTEADOR
# Passo 1: adicionar repositório oficial do FRRouting
curl -s https://deb.frrouting.org/frr/keys.gpg | sudo tee /usr/share/keyrings/frrouting.gpg > /dev/null

echo "deb [signed-by=/usr/share/keyrings/frrouting.gpg] https://deb.frrouting.org/frr $(lsb_release -s -c) frr-stable" | sudo tee /etc/apt/sources.list.d/frr.list

# Passo 2: instalar
sudo apt update
sudo apt install -y frr frr-pythontools

# Passo 3: habilitar o daemon RIP
# (o FRR tem daemons separados para cada protocolo)
sudo sed -i 's/ripd=no/ripd=yes/' /etc/frr/daemons

# Passo 4: também habilitar o zebra (gerencia as rotas no kernel)
sudo sed -i 's/zebra=no/zebra=yes/' /etc/frr/daemons

# Passo 5: reiniciar o FRRouting
sudo systemctl restart frr
sudo systemctl enable frr

# Verificar se está rodando
sudo systemctl status frr
07
Configurar IPs nas interfaces de cada roteador (Netplan)
Cada interface do roteador precisa de um IP estático na sua respectiva rede
▶
// O QUE É O NETPLAN?
O Ubuntu Server 22.04 usa o Netplan para configurar redes. Você edita um arquivo YAML e ele aplica as configurações. É mais moderno que o antigo /etc/network/interfaces. As interfaces no Ubuntu se chamam enp0s3, enp0s8, enp0s9... — a numeração segue a ordem dos adaptadores no VirtualBox.

Para descobrir os nomes das interfaces na sua VM, rode: ip link show

Exemplo de configuração para R1 (adapte os IPs para cada roteador):

/etc/netplan/00-installer-config.yaml — R1
network:
  version: 2
  ethernets:
    # Adaptador 1: interface para LAN1 (192.168.1.0/24)
    enp0s3:
      dhcp4: no
      addresses: [192.168.1.1/24]

    # Adaptador 2: link WAN para R2 (10.1.12.0/30)
    enp0s8:
      dhcp4: no
      addresses: [10.1.12.1/30]

    # Adaptador 3: link WAN para R5 (10.1.15.0/30)
    enp0s9:
      dhcp4: no
      addresses: [10.1.15.1/30]
APLICAR CONFIGURAÇÃO
sudo netplan apply
# Verificar se os IPs foram aplicados:
ip addr show

Também habilite o IP forwarding — sem isso o Linux não repassa pacotes entre interfaces (não funciona como roteador):

HABILITAR IP FORWARDING — TODOS OS ROTEADORES
# Habilitar permanentemente
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

# Verificar: deve mostrar "net.ipv4.ip_forward = 1"
cat /proc/sys/net/ipv4/ip_forward
08
Configurar o RIPv2 via vtysh (interface do FRRouting)
O vtysh é o terminal do FRRouting — funciona igual ao Cisco IOS
▶
// O QUE É O VTYSH?
O vtysh é o shell de configuração do FRRouting. Quando você digita sudo vtysh, entra num ambiente igual ao do Packet Tracer — com os mesmos comandos Cisco: configure terminal, router rip, show ip route. Isso é proposital, para facilitar a transição do simulador para o ambiente real.

Rode em R1 (depois adapte para cada roteador com as redes corretas):

CONFIGURAR RIPv2 NO R1 — VIA VTYSH
# Entrar no shell do FRRouting
sudo vtysh

# Dentro do vtysh:
R1# configure terminal

# Configurar RIP
R1(config)# router rip
R1(config-router)# version 2               # obrigatório: usar RIPv2
R1(config-router)# no auto-summary         # desabilitar sumarização automática

# Anunciar TODAS as redes conectadas
R1(config-router)# network 192.168.1.0/24    # LAN1
R1(config-router)# network 10.1.12.0/30     # WAN para R2
R1(config-router)# network 10.1.15.0/30     # WAN para R5

# Interface passiva na LAN (não envia RIP updates para hosts)
R1(config-router)# passive-interface enp0s3

R1(config-router)# exit
R1(config)# exit

# Salvar configuração
R1# write memory
R1# exit

Verificar se o RIP está funcionando:

COMANDOS DE VERIFICAÇÃO
sudo vtysh -c "show ip route"       # rotas aprendidas (R = RIP)
sudo vtysh -c "show ip rip"         # tabela RIP
sudo vtysh -c "show ip protocols"   # confirmar versão e passive-interface

Configurar os Servidores de E-mail

Postfix (SMTP) + Dovecot (POP3) — EMAIL1 e EMAIL2
09
Instalar e configurar o EMAIL1 (domínioA.com)
Postfix envia e-mails (SMTP, porta 25) — Dovecot entrega e-mails (POP3, porta 110)
▶
// POR QUÊ POSTFIX + DOVECOT?
O Postfix é o servidor SMTP — ele envia e recebe e-mails entre servidores (como o carteiro). O Dovecot é o servidor POP3/IMAP — ele armazena os e-mails e os entrega ao cliente (como a caixa de correio). Juntos, eles formam um servidor de e-mail completo. São os softwares mais usados no mundo real para isso.

Rode na VM EMAIL1 (IP: 192.168.2.10, gateway: 192.168.2.1):

INSTALAR POSTFIX + DOVECOT NO EMAIL1
# Instalar os dois serviços
sudo apt install -y postfix dovecot-pop3d dovecot-imapd

# Durante a instalação do Postfix, vai aparecer uma tela de configuração:
# Escolha "Internet Site"
# System mail name: dominioA.com
CONFIGURAR POSTFIX — /etc/postfix/main.cf
# Abrir o arquivo de configuração
sudo nano /etc/postfix/main.cf

# Adicionar/editar estas linhas:
myhostname = email1.dominioA.com
mydomain = dominioA.com
myorigin = $mydomain
inet_interfaces = all
mydestination = $myhostname, dominioA.com, localhost
mynetworks = 192.168.0.0/16, 10.0.0.0/8, 127.0.0.0/8
home_mailbox = Maildir/

# Salvar: Ctrl+O, Enter, Ctrl+X
CONFIGURAR DOVECOT — /etc/dovecot/conf.d/10-mail.conf
sudo nano /etc/dovecot/conf.d/10-mail.conf

# Encontre a linha mail_location e mude para:
mail_location = maildir:~/Maildir
CRIAR USUÁRIO aluno@dominioA.com
# Criar o usuário Linux (o e-mail usa contas do sistema)
sudo useradd -m -s /bin/bash aluno
echo "aluno:cisco" | sudo chpasswd

# Criar a estrutura de pastas de e-mail
sudo -u aluno maildirmake /home/aluno/Maildir

# Reiniciar os serviços
sudo systemctl restart postfix dovecot
sudo systemctl enable postfix dovecot

# Verificar se estão rodando
sudo systemctl status postfix
sudo systemctl status dovecot
// EMAIL2 — MESMA CONFIGURAÇÃO, DOMÍNIO DIFERENTE
Repita tudo no EMAIL2, substituindo: dominioA.com → dominioB.net, aluno → avaliador, senha cisco → packet, IP: 192.168.3.10, gateway: 192.168.3.1.

Configurar os Servidores DNS

BIND9 com registros A e MX — DNS1 e DNS2
10
Instalar e configurar o BIND9 (DNS1)
BIND9 é o servidor DNS mais usado no mundo — traduz nomes em IPs e define servidores de e-mail
▶
// O QUE SÃO REGISTROS MX?
Quando você envia um e-mail para aluno@dominioA.com, o servidor de e-mail consulta o DNS: "qual servidor cuida do dominioA.com?" O DNS responde com o registro MX, que aponta para o EMAIL1. Sem o MX, os e-mails entre domínios não funcionam. O registro A diz qual é o IP do nome. O MX diz qual servidor de e-mail usar para aquele domínio.
INSTALAR BIND9 NO DNS1
sudo apt install -y bind9 bind9utils bind9-doc
CRIAR ZONA — /etc/bind/zones/db.rede.local
sudo mkdir -p /etc/bind/zones
sudo nano /etc/bind/zones/db.rede.local

# Cole o conteúdo abaixo:
$TTL    604800
@   IN  SOA dns1.rede.local. root.rede.local. (
            2024010101  ; Serial
            604800      ; Refresh
            86400       ; Retry
            2419200     ; Expire
            604800 )    ; Negative Cache TTL

; Servidores de nomes
@       IN  NS  dns1.rede.local.

; Registros A (nome → IP)
dns1        IN  A   192.168.1.5
web1        IN  A   192.168.1.10
email1      IN  A   192.168.2.10
email2      IN  A   192.168.3.10
dns2        IN  A   192.168.4.5

; Registros MX (quem cuida dos e-mails de cada domínio)
dominioA.com.   IN  MX  10  email1.rede.local.
dominioB.net.   IN  MX  10  email2.rede.local.

; Alias para os domínios de e-mail
dominioA.com.   IN  A   192.168.2.10
dominioB.net.   IN  A   192.168.3.10

; Registros para o cenário (nomes do trabalho)
web.local.      IN  A   192.168.1.10
CONFIGURAR /etc/bind/named.conf.local
sudo nano /etc/bind/named.conf.local

# Adicionar:
zone "rede.local" {
    type master;
    file "/etc/bind/zones/db.rede.local";
};

zone "dominioA.com" {
    type master;
    file "/etc/bind/zones/db.rede.local";
};

zone "dominioB.net" {
    type master;
    file "/etc/bind/zones/db.rede.local";
};
INICIAR BIND9
# Verificar a configuração antes de iniciar
sudo named-checkconf
sudo named-checkzone rede.local /etc/bind/zones/db.rede.local

# Iniciar
sudo systemctl restart bind9
sudo systemctl enable bind9

# Testar a resolução de nomes
nslookup web.local 192.168.1.5
nslookup -type=mx dominioA.com 192.168.1.5

Testar tudo — Checklist de entrega

Validar conectividade, roteamento, DNS, e-mail e HTTP
13
Executar todos os testes do cenário
Cada teste valida uma parte diferente — RIP, DNS, SMTP/POP3 e HTTP
▶
  • Teste 1 — RIPv2: Em R5, rode sudo vtysh -c "show ip route" e verifique se aparecem rotas com código R para 192.168.1.0, 2.0, 3.0, 4.0
  • Teste 2 — Ping cross-LAN: Do PC-A (LAN4), rode ping 192.168.1.10 (WEB1 na LAN1) — deve responder
  • Teste 3 — Ping para EMAIL1: Do PC-B (LAN5), rode ping 192.168.2.10 — deve responder
  • Teste 4 — DNS resolução A: De qualquer PC, rode nslookup web.local 192.168.1.5 — deve retornar 192.168.1.10
  • Teste 5 — DNS resolução MX: nslookup -type=mx dominioA.com 192.168.1.5 — deve retornar email1.rede.local
  • Teste 6 — HTTP: Do PC-A, rode curl http://web.local — deve exibir a página do WEB1
  • Teste 7 — Envio de e-mail: Do PC-B, envie e-mail para aluno@dominioA.com usando sendmail ou swaks
  • Teste 8 — Recebimento POP3: Do PC-A, conecte ao POP3: telnet 192.168.2.10 110, depois USER aluno, PASS cisco, LIST
  • Wireshark: Capture pacotes na interface WAN de qualquer roteador e filtre por rip para ver os updates RIP, e por smtp ou pop3 para ver os e-mails
TESTE DE E-MAIL VIA TERMINAL (PC-B → aluno@dominioA.com)
# Instalar swaks (ferramenta de teste SMTP)
sudo apt install -y swaks

# Enviar e-mail de teste
swaks \
  --to aluno@dominioA.com \
  --from avaliador@dominioB.net \
  --server 192.168.3.10 \
  --body "Teste de e-mail entre dominios" \
  --header "Subject: Teste Cenario 5"
COLETAR E-MAIL VIA POP3 (PC-A)
# Conectar ao servidor POP3
telnet 192.168.2.10 110

# Depois de conectar, digitar:
USER aluno
PASS cisco
LIST          # listar mensagens
RETR 1        # ler a mensagem 1
QUIT

⚡ Dicas importantes para o dia da apresentação

1. Inicie os roteadores primeiro — espere o RIP convergir (~30 segundos) antes de testar os PCs.
